# 人物识别与计数修复：0.1.2

2026-10-24。测试候选版本0.1.2 / versionCode3。最低Android 8.0 / API26；包名、公开AOSP测试签名及历史存储格式延续旧版。此文档记录发布前的本地验证；未由开发代理安装手机或启动相机。

## 0.1.1已覆盖的修复

旧0.1.0把人物获取与计数就绪合成一个条件，要求鼻、双肩、双髋、双膝、双踝9点同时达标，且肩踝高度超过整个画面30%；短暂低分点还会清空校准。实际MoveNet静态照片推理复现：横图可通过，竖屏和远景摆放有合理关键点却被旧几何门槛拒绝。

0.1.1已分开人物获取与双脚计次证据：至少一侧肩与一侧髋可靠即可找到人物，计次仍需要两踝有效及合理直立姿态；鼻、膝、另一侧肩髋不再必选。采用人体比例归一化、采集时间EMA与进入/退出迟滞；短遮挡保留基线但取消未完成周期，双脚落地后才开始新周期。暂停、休息、恢复、过期帧与离开画面处理没有因本轮研究重新改造。

## 本次差距检查与实际变化

| 检查项 | 证据与处理 |
|---|---|
| 人物获取/计数就绪分离 | 既有准入类、提示及部分非必要关节缺失回归覆盖，保留原实现；诊断新增person_visible/countable/ready三个独立标记 |
| 短遮挡与丢帧 | 新回归复现：一次无效帧后再丢帧，可靠结果回来时可能沿用超过800ms的旧校准。现按最后可靠证据时间检查有效期；超过800ms缺少可靠证据重新校准，800ms边界以内落地后可保留。所有缺失阶段都不补造跳跃 |
| 关节置信度反馈 | 原内存诊断只列髋/踝，躯干缺失时无法看肩部分数。补肩部左右分数和上述三种状态；界面说明同步更新。默认关闭、4Hz最多240行、仅内存，不录图像、不自动上传 |
| 低幅度与帧率变化 | 既有正常60/120/180/220rpm×15/30fps、低幅度150rpm×15/24/30fps与变帧间隔回归通过，保留算法及阈值，不重复换算法 |
| 相机/模型坐标映射 | 既有YUV步长、cropRect、四方向旋转、预览独立镜像、裁剪点映回原画面均保留。新回归复现横向位移按画面宽度归一化、人体高度按画面高度归一化，直接比较导致宽高比改变时准入不同。现将横向量转换为画面高度单位；竖屏、横屏、方形画面对同一物理比例位移得到一致结论 |

修改集中在 `JumpDetector`、`NumericDiagnostics`、诊断说明与回归测试。真实图像测试桥同步带入帧宽高，使用与Android相同的横向度量。没有复制或修改模型，也没有通过继续降低分数阈值来掩盖上述边界错误。

`docs/test-evidence/gap-regressions-before.txt` 保留在未修改0.1.1计数器时复现的两个失败断言；最终 `core-tests.txt` 为49项、390断言全部通过。

## 静态研究状态已更新

此前构建0.1.1时尚未取得参考应用安装包，这是历史状态。之后通过用户提供的本地文件完成了Rea/JADX私有静态研究。仅观察到输入坐标变换、可见度过滤、历史结果复用、人体尺度运动状态和按配置选择不同计数实现等高层结构。静态研究不证明实际模式启用哪些路径、原生内部算法、真实相机效果或计数准确率；没有安装或运行第三方应用及其原生库。

轻跃继续采用自己的实现与许可明确的官方MoveNet模型。缓存坐标不作为新起跳/落地证据，不照搬第三方阈值。第三方安装包、模型、反编译代码、原始日志、分享链接及用户本地文件路径均不进入公开候选文档、源码ZIP或APK。

参考来源：[MoveNet官方教程](https://www.tensorflow.org/hub/tutorials/movenet)、[Google Android示例](https://github.com/tensorflow/examples/blob/master/lite/examples/pose_estimation/android/app/src/main/java/org/tensorflow/lite/examples/poseestimation/ml/MoveNet.kt)、[ML Kit图像方向说明](https://developers.google.com/ml-kit/vision/pose-detection/android)、[MediaPipe重复动作计数说明](https://github.com/google-ai-edge/mediapipe/blob/master/docs/solutions/pose_classification.md)、[Rea Android指南](https://github.com/morluto/rea/blob/main/docs/android-analysis.md)。这些均是设计或工具参考，不是已经验证的跳绳精度保证。

## 已验证范围与边界

JVM测试覆盖训练、休息、暂停、持久化序列、合成关键点正常/低幅度跳、关节缺失、遮挡、帧率变化、站立/走动/深蹲负例、像素旋转与裁剪、宽高比一致性及诊断字段。真实图像测试仅使用一张TensorFlow官方测试照片：原图与三种画布变体，共4种摆放，另加空白图；照片中的人并未跳绳。75帧静态动态裁剪应保持0计数。桌面实际模型推理使用LiteRT2.3.0，APK使用1.4.0，不等同于Android设备执行。

没有模拟器、手机相机/TTS、真人跳绳视频或准确率实测。CPU相机移动检查是保守外侧纹理平移判据，不能覆盖无纹理背景、所有摇晃或多人场景。SinglePose不能可靠确认多人，双脚起落不证明绳圈通过，也不支持双摇或交替脚验证。

测试APK为公开AOSP签名材料，仅开发验收，不能作为发布者身份或正式更新信任；未创建新持久凭证。构建继续使用获准项目局部Temurin及固定Maven依赖，AOSP android-all是非标准编译API输入，尚未作标准SDK/Gradle等效验证。

## 最小设备验收

1. 由获准测试者核对SHA256后覆盖安装0.1.2，保留原数据，确认已有历史仍在。前后摄像头各站稳数秒，画面与骨架同向；检查“人物找到”和“计数就绪”分别反馈。
2. 固定手机、普通室内光线，人工独立计数正常100次、低幅度100次；再做站立30秒、走动与深蹲负例，记录漏报/多报。近远两种摆放至少各确认一次就绪。
3. 短遮挡后落地继续、超过1秒遮挡后重新校准；暂停/继续、切后台和组间休息均不得补计半次或丢累计。需要排查时主动开启内存数值诊断，复制数值即可，不必录像。TTS用已有离线中文声音单独确认。
